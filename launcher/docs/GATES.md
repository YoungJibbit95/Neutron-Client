## Regeln für Prüfberichte

Jeder Test nennt Umgebung/Architektur, Eingaben, Kommando oder Interaktion, Ergebnis und Evidenzpfad. Build, Paketierung, Headless-/Offscreen-Prüfung und tatsächlicher Client-Start werden getrennt ausgewiesen. Nicht ausgeführte Tests heißen „nicht ausgeführt“; aus vorhandenem Code oder README werden keine bestandenen Tests abgeleitet.

Fehlerfälle erhalten isolierte Verzeichnisse und synthetische Profile. Das persönliche `test_run/` wird nicht als Testfixture verwendet. Spätere Tests dürfen laufende Prozesse, Daten oder Builds fremder Chats nicht beenden oder ersetzen.
