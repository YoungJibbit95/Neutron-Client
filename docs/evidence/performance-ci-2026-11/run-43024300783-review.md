# Initial PR native performance evidence — run 43024300783

**Pixel and contract checks passed. This run does not establish a general speed or FPS improvement.** Several workloads have higher tails, and bloom/blur/glass consistently allocate additional heap bytes. This report retains those regressions and distinguishes observation from causal inference.

## Important negative findings and phase effects

- **Glass 960×640:** completed p95 rises 9.97% and p99 31.54%; both are higher in three of four pairs. Submission p95/p99 rise 12.30%/32.26%, also three of four for p99. One candidate maximum reaches 106.703 ms. This is a repeated negative signal within this run; dismissing it as noise would be unjustified. Four software-GL pairs cannot establish the responsible code, GC, driver or scheduling contribution.
- **UI 854×480:** completed p95 rises 10.10% and is higher in all four pairs. Submission p95 rises 16.77% and p99 39.40%, both higher in all four pairs. Smaller p50 changes do not cancel these tail regressions.
- **Bloom 854×480:** completed p95/p99 rise 3.22%/11.85%, each higher in three of four pairs. Gaussian 854 p95 rises 6.70%, also three of four.
- **Mixed phase distributions can mislead:** blur alternates radii 7/11 and bloom alternates iterations 2/3. At 854×480, Gaussian’s mixed p50 appears 3.08% lower while each individual radius has a median paired p50 increase of about 1.5%. ### Scope-size inference

An isolated local probe used Java Instrumentation `getObjectSize` on instances allocated without constructors or GL calls, under Temurin 8 with compressed ordinary/class pointers and 8-byte alignment. `RenderState` grows **128 → 144 B (+16 B)**; `UiDrawState` remains **80 B**. Probe source, flags and exact outputs are embedded in the JSON. This measures shallow object layout, not render timing.

The pack-off benchmark’s production call paths create two `RenderState` scopes for Gaussian (blur plus output quad), two for warmed glass (surface plus blur), and four for bloom (collection, flush and two role-mask groups). These counts match **2 × 16 = 32 B** and **4 × 16 = 64 B**. `Shaders.beginClientRender()` returns no client-state object with the pack disabled. This is a well-supported size/count inference for the constant heap deltas, not allocation-stack attribution. It does **not** identify the cause of higher timing tails. Additional state operations may cost time; this artifact does not isolate that cost from driver, scheduling or GC effects. No speculative performance change is justified by this result alone.
